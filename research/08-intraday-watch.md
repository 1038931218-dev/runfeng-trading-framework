# 盘中实时监控 · 实现方案与运行手册（2026-11-07）

> 责任：**润行（总指挥·操盘手）**｜目标：交易日实时盯计划条件，命中即叫醒团队并准备下单
> 结论先说：**监控、触发、叫醒、下单、成交全链路可无人执行**——用户每天早上登录通达信一次后，当日下单免密。

---

## 1. 能实现什么、不能实现什么

| 能力 | 能否 | 说明 |
|---|---|---|
| 交易时段内按间隔拉实时行情 | ✅ | Sina `hq.sinajs.cn`（免费、秒级延迟），每 N 分钟轮询 |
| 周末/非交易时段自动跳过 | ✅ | 周一至周五 + `09:15–11:30 / 13:00–15:00`；节假日可配置 |
| 命中当日计划条件立刻告警 | ✅ | 写 `data/alerts-YYYY-MM-DD.jsonl` + 退出，后台任务结束会**立刻叫醒润行** |
| 告警后自动打开通达信、预填买卖单 | ✅ | 润行用手机 MCP 操作 App（已验证可读可填） |
| **无人值守完成成交** | ✅ | **登录态下下单免密**（用户每天早上登录一次后，润行直接提交）；仅「当天首次登录」需要用户 |
| 跌破止损自动卖出 | ⚠️ | 通达信可设「云条件单→自动委托」，但用户当前选的是「人工委托」，触发只提醒 |
| 节假日自动识别 | ⚠️ | 目前靠 plan 里 `session.holidays` 手工列表；后续可接 akshare 交易日历 |
| 断网/锁屏/省电杀进程 | ⚠️ | proot 无前台服务，进程可能被杀；靠定时任务重启 + 健康检查 |

## 2. 组件

| 文件 | 作用 |
|---|---|
| `tools/watch_intraday.py` | 监控器：读计划 → 轮询行情 → 比对条件 → 告警/退出 |
| `data/plan-YYYY-MM-DD.json` | 当日计划：账户、监控列表、触发规则、guard、交易时段 |
| `data/alerts-YYYY-MM-DD.jsonl` | 告警流水（每行一条命中记录，可追溯） |
| `data/watch-state.json` | 去重/冷却状态（同一规则 cooldown 内不重复报） |

**规则字段**：`id / label / symbol / op(<=,>=,<,>) / price / floor（买区下沿，可选）/ action(sell_ready,buy_ready,notify,risk_off) / side / qty / cooldown_sec / note`
**guard**：`no_new_position_before=10:00`（CPI/PPI 窗口不新开仓）、`buy_block_if_index_below=3574.27`（破位取消买入）、`max_new_positions_today=2`
**同一标的同方向只报「最深」一条**（避免 3.16 与 3.10 同时命中重复叫醒）。

## 3. 运行方式

```bash
cd <项目目录>

# ① 手动单次检查（适合定时任务）
python3 tools/watch_intraday.py --once --plan data/plan-2026-11-09.json

# ② 前台盯盘（3 分钟一次，命中即退出并打印 ALERT）
python3 tools/watch_intraday.py --interval 180 --plan data/plan-2026-11-09.json

# ③ 后台盯盘（Agent 用后台任务跑，命中/收盘后任务结束 → 自动叫醒润行）
python3 tools/watch_intraday.py --interval 180 --keep-alive --max-runtime 28800

# ④ 离线自测规则（用 11-06 快照，不联网、不交易）
python3 tools/watch_intraday.py --test-with-snapshot --once --plan data/plan-2026-11-09.json
```

- 退出码：`0` 无触发/收盘；`10` 有触发；`1` 异常。后台任务工具能捕获结束 → 通知 Agent。
- 15:00 后自动退出；周末/非交易时段不查行情（每 60 秒检查一次是否开盘）。

## 4. 触发后的处理链（润行 SOP）

1. 后台任务结束 → 润行被叫醒 → 读 `data/alerts-*.jsonl` 最新一条。
2. `mcp__phone__notify` 发通知给用户（一句话：触发什么、准备怎么操作）。
3. 打开通达信 → 交易 → 卖出/买入 → 按 plan 的价格/数量填单并**直接点提交**（用户已授权，不再逐单请示）。
4. 登录态下**下单免密，直接提交**；若 App 提示重新登录/登录失效（读不到资产页）→ `mcp__phone__handoff` 请用户登录一次，登录后继续。
5. 查「当日委托/成交」→ 记录成交价/费用/余额 → 写回 `reports/` 或账户日志。
5.1 **紧急止损类告警**（`action=emergency_sell` 或 `risk_off`）：**不通知等待、直接执行**——emegency_sell 用对手价/市价卖出该持仓；risk_off 立即停止当日买入并评估是否减仓。事后补通知用户。
5.2 若手机不在线/App 掉登录：L2 兜底是通达信「云条件单·自动委托」（服务器端），不依赖本机进程；需提前设置（万科 3.16 单待升级）。
6. 若还有后续规则未触发：重新起后台监控（`--interval` 同前）。

**异常**：网络失败自动重试下一轮；App 断连按 `research/07-trade-sop.md` 四步恢复；登录失效才需要用户（登录一次），其余全自动。

## 5. 每日时间表（建议）

| 时间 | 动作 |
|---|---|
| 09:20 | 定时任务叫醒：读 plan、复测通达信、启动后台监控 |
| 09:25–09:30 | 集合竞价：检查万科开盘价、条件单状态 |
| 10:00 | guard 解除（可新开仓），监控继续 |
| 11:30–13:00 | 午休（监控自动空转，不开行情请求） |
| 14:55–15:00 | 收盘前最后检查；15:00 后监控退出 |
| 15:05 | 定时任务：汇总当日告警、成交、持仓，更新 `reports/` |

## 6. 已知限制与改进项

1. **成交依赖登录态**——用户每天早上登录一次后当日下单免密；若 App 中途掉登录，需要用户重新登录一次。可以把云条件单改「自动委托」作为登录失效时的兜底（用户已授权可评估）。
2. 行情用 Sina 免费源，**非逐笔 Level-2**，极端快市可能滞后；对 5044 元、1 手级别的计划足够。
3. 节假日清单手工维护；2026 年内剩余节假日需补进 `plan.session.holidays`。
4. Android 省电策略可能杀后台进程；建议把 DSH 加入「电池不优化」白名单，并保留 10:30 / 13:30 健康检查定时任务。
5. 单进程串行：一轮行情拉 7 个代码约 1 秒，不影响 3 分钟节奏。

## 6.1 每日计划同步（2026-11-07 新增）

每天收盘后（15:05 定时任务）按固定闭环更新，**不用改代码、只要改 `data/watchlist.json`**：

```
日报/账户方案（新的买卖点、止损）
   ↓ 人工调整（15:05 任务里做）
data/watchlist.json      候选买点区间 + 持仓止损 + 指数规则
data/account-state.json  实盘持仓/现金（15:05 从通达信读取后写入）
   ↓
python3 tools/make_plan.py            # 自动生成 data/plan-<下一交易日>.json
   ↓
次日 09:20 定时任务：读 plan → 启动 watch_intraday.py
```

- `make_plan.py` 会自动刷新：上证 MA20、250 日低（行情现场算）、候选股 MA20/MA60（缺区间时用均线兜底），并把 portfolio JSON 的 stop_loss 作为持仓兜底止损。
- 计划生成后**润行终审**（价位/手数/权限/红线），确认后才生效；`watch_intraday.py` 只读当天日期文件，不读旧计划。
- 新交易日若没有计划文件，09:20 任务会自动 `make_plan.py --date <今天>` 现场生成，不会用过期计划硬跑。
